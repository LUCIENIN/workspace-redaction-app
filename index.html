HOW THE LOCAL WIKI WORKS

不是把文档堆进向量库，
而是先编译成可维护的 Wiki。

当前项目遵循“原始资料 → Wiki → Schema”的三层架构。摄入只做一次并增量更新；查询时再组合分词、向量和图谱，而不是每次从所有原文重新推导。

INCREMENTAL

增量而非重做

源文件内容哈希未变化时跳过，减少重复处理和不必要的模型调用。

TRACEABLE

来源可追溯

生成页通过 frontmatter 和 sources 字段回链原始资料，但公开时不携带私有来源。

HUMAN-GATED

人类策展

LLM 负责维护结构，人负责定义目的、判断隐私和决定是否发布。

PUBLICATION WORKFLOW

本地知识库的正确脱敏闭环

目标不是复制一份“看起来干净”的私有库，而是建立一个内容更少、用途更明确、证据可回读的公开产物。

  1. 01

    锁定公开目的

    只回答“别人需要学会什么”，不从“我本地有什么”反推全部公开。

  2. 02

    按目录分区

    raw、private archive 和运行状态直接排除；Wiki 页面进入人工复核区。

  3. 03

    抽取方法，不搬运事实

    保留步骤、判断门和验证方式；移除客户、财务、健康、账号和项目专有细节。

  4. 04

    一般化身份与环境

    绝对路径改为变量，账号改为角色，真实数字改为范围或结构说明。

  5. 05

    生成内容零知识快照

    只输出页数、索引状态和健康结论，不输出文件名、标题、路径或内容片段。

  6. 06

    本地扫描与人工审阅

    自动规则查密钥和身份痕迹；人工复核语义泄漏、版权和业务边界。

  7. 07

    最小提交

    在隔离仓库中只暂存确认文件，检查提交作者邮箱与 Git 历史。

  8. 08

    远端门禁与回读

    CI 再扫描；发布后从 GitHub、Raw 和 Pages 独立确认最终公开内容。

EXECUTION BASIS

每一步都有代码和状态依据

这里的“依据”指当前项目里的真实实现和安全边界，不是法律合规证明，也不意味着自动扫描可以替代业务判断。

A

安全候选筛选

同步脚本排除认证文件、环境文件、二进制、依赖、构建产物、超大文件和符号链接。

sync-codex-knowledge.py
B

凭据替换

对 API Key、Token、Bearer、云访问键和常见密码赋值做显式替换，并累计脱敏数量。

redact_secrets()
C

图谱可再生成

技能、工作流、项目和规则节点由受控源生成；详细原始文件保存在 archive，不进入主图谱。

build-codex-graph.py
D

健康不是单一数字

同时检查断链、孤立页、frontmatter、正向搜索、噪声查询、图谱指纹与向量一致性。

knowledge_health.py
E

五步日常同步

归档同步 → frontmatter 修复 → 图谱重建 → 健康与搜索审计 → 有界本地 AI 维护。

run-daily-sync.zsh
F

状态必须分层回读

文件存在、图谱更新、搜索可用、向量完成和远端发布是不同证据，不能互相替代。

CAUTIONS

自动化不能替你理解“这句话意味着什么”

字符串扫描擅长发现格式稳定的泄漏；语义、版权、业务身份和组合推断仍然需要人判断。

!

生成页也可能包含私密事实

Wiki 是对原始资料的结构化重述，不因“由 LLM 生成”就自动变成公开资料。

!

向量库不是匿名数据

Embedding、chunk、对话和检索缓存属于运行状态，默认不复制、不上传、不纳入公开演示。

!

健康警告不能被包装成完成

当前脱敏快照记录的是 quality_warning 与 9/10 搜索基准；页面明确保留该事实。

!

版权边界独立于隐私边界

移除身份信息并不自动获得复制原文、图片、论文、商业文档或第三方代码的许可。
